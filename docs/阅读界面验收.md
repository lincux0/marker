### 复现

1. 按[工程指南](工程开发指南.md)构建 Web；把 `docs/samples/u0-reading.md` 临时复制到 `src/Marker.Web/dist/u0-reading.md`，供测试读取。这个文件不会作为应用资源交付，下一次 Vite build 会清除它。
2. 使用既有 Vite preview 5173 与 Playwright MCP；主 MCP 页面导航到 `http://127.0.0.1:5173/index.html?phase=baseline`，以 filename 执行 `D:/marker/scripts/test-reading-ui.js`。
3. 更新样式并构建后，重新复制样张，主页面使用 `?phase=final` 执行同一脚本。脚本关闭独立测试 context；主页面和 Vite 由本轮执行者关闭。
4. 同机、同浏览器、相同样张对比 JSON；遇到波动记录原始样本，不把一次耗时当成稳定性能结论。

U0 没有修改产品代码或默认值，因此不重建 EXE/Setup。真实输入法、读屏器、最低支持系统、多屏与长时间性能尚未验证；这些继续随对应实施阶段检查。

- 表格保持等宽可编辑结构，减弱纵线、保留横向边界，单元格内边距 `.55em .6em`；从当前表格的 GFM 分隔行产生固定左/中/右对齐类，不改列宽模型。测试表格为12列、3正文行，含转义竖线和长单元格；GFM 表格内代码的竖线也必须转义。窄窗仍可能形成很窄的列，这是既有结构边界，未引入整表替换、横滚布局重做或 TSV 功能。
