# 阅读界面基线与验收

本文件记录[UI 优化方案](阅读界面UI优化方案.md)的实际验收结果，未测试项目不推定通过。

## U0：2026-10-09 基线

- 实施起点 `bc0cce6`；用户确认保持现有默认值及文字宽度，U1 仅优化基础样式。
- 使用[阅读样张](samples/u0-reading.md)，覆盖 H1–H6、混排、行内语法、长 URL、转义、硬软换行、嵌套列表、两/三位编号和引用内列表。
- 真实 x64 Release EXE 打开样张，截图 `artifacts/reading-ui/u0-native.png` 与 `u0-webview.png`；确认 16 px 正文、24 px 行高。恢复提示选择“取消”，保留原有草稿；样张未修改，应用已正常关闭。
- 现有布局与舒适候选截图分别为 `u0-current-layout.png`、`u0-comfort-candidate.png`。候选仅在隔离浏览器中临时应用 17 px / 1.7 / 0.75em / 约720 px文字区，没有写设置或产品代码；本轮采用用户选择的现有排版。
- 真实截图观察：H1/H2 宋体与其他层级有辨识度，但 H1 偏大，标题与源码空行叠加留白明显；引用、删除线和列表使用弱色。U1 通过倍率、行盒间距和正文色统一调整，不把 HTML margin 规则直接套入编辑器。

### 检查与性能

`scripts/test-reading-ui.js` 使用现有 Playwright MCP，24 个覆盖场景通过：4 种宽度×3 种字号，明暗×5 种配色，高对比两种主题。检查设置正确应用、纸面不随字体/配色改变、宽屏纸面 980 px、原文快照一致。它不等于每个组合截图或无障碍对比度全部通过。

| 指标 | U0 结果 |
|---|---|
| Web 宽度720/960/1400/2000 px的纸面 | 652 / 872.8 / 980 / 980 px |
| 正文 / H1 | 16 / 36 px |
| 短文初始化 / 逐字p50 / p95 | 30 / 13 / 21 ms |
| 10万UTF-16单元多段文初始化 / 逐字p50 / p95 | 57 / 18 / 42 ms |
| 输入样本数 | 每份20次，精确核验追加20字；长文单次最高129 ms |

原始数据在 `artifacts/reading-ui-baseline.json`；截图在 `artifacts/reading-ui-baseline.png`。环境：Intel Core i5-12500H、Windows build 26300.9550、Playwright Chromium 154.0.8037.98。真实窗口截图物理尺寸1920×1380，WebView客户区1522×1067 CSS px；不将截图推断为混合DPI验收。

计时包含 Playwright 自动化往返和两个 requestAnimationFrame；初始化为单次观察，输入为20次。此数据不包含真实键盘、Windows IME、原生序列化、Markdig与磁盘，不可按方案预算声称真实 EXE 输入性能已达标。

### 复现

1. 按[工程指南](工程开发指南.md)构建 Web；把 `docs/samples/u0-reading.md` 临时复制到 `src/Marker.Web/dist/u0-reading.md`，供测试读取。这个文件不会作为应用资源交付，下一次 Vite build 会清除它。
2. 使用既有 Vite preview 5173 与 Playwright MCP；主 MCP 页面导航到 `http://127.0.0.1:5173/index.html?phase=baseline`，以 filename 执行 `D:/marker/scripts/test-reading-ui.js`。
3. 更新样式并构建后，重新复制样张，主页面使用 `?phase=final` 执行同一脚本。脚本关闭独立测试 context；主页面和 Vite 由本轮执行者关闭。
4. 同机、同浏览器、相同样张对比 JSON；遇到波动记录原始样本，不把一次耗时当成稳定性能结论。

U0 没有修改产品代码或默认值，因此不重建 EXE/Setup。真实输入法、读屏器、最低支持系统、多屏与长时间性能尚未验证；这些继续随对应实施阶段检查。

## U1：2026-10-09 基础样式

### 实现与视觉检查

- 按用户确认保留生产默认 16 px / 1.5 / 0.5em、文字宽度和宽屏 980 px 纸面。H1–H6 改为正文的 2 / 1.7 / 1.45 / 1.25 / 1.1 / 1 倍；H1/H2 保留字体选择。编辑器沿用 CodeMirror 行盒 padding，缩减标题额外留白，仍不使用垂直 margin。
- 引用和删除线使用正文色；引用使用中性边线、极淡背景，行内代码缩小内边距与圆角，链接使用完整下划线及长地址断行。现有列表缩进保留，避免与源码空白重复计算；表格、代码块、图片等留到 U2。隐藏 HTML 预览同步基础样式，不新增可见阅读模式。
- 最终 EXE 实际打开样张，确认六级标题为 32 / 27.2 / 23.2 / 20 / 17.6 / 16 px，正文 16 px、行高 24 px、纸面 980 px；聚焦编辑器后 `Ctrl+Alt+M` 往返正常。原生与 WebView 截图 `artifacts/reading-ui/u1-native.png`、`u1-webview.png` 已检查，未改样张，取消恢复提示并保留旧草稿。
- 浏览器明暗、720 px 窄窗和引用/列表截图分别为 `artifacts/reading-ui-final-light.png`、`reading-ui-final-dark.png`、`reading-ui-final-720.png`、`reading-ui-final-quote-list.png`。检查标题层级、引用可读性与无整页横向溢出，不将截图视为全部 DPI 或读屏验收。

### 同机配对性能复核

单次初始化存在波动，额外用 U0 提交 `fc686a0` 的旧 CSS 与最终 CSS，在相同浏览器、相同内容的隔离 context 中配对检查。每组预热 3 次后采 5 次初始化；输入预热 4 次后采 20 次，并检查追加文本保真。原始样本见 `artifacts/reading-ui/paired-performance.json`。

| 内容 | U0 / U1 初始化中位数 | U0 / U1 输入 p95 |
|---|---|---|
| 短文 | 18 / 18 ms | 13 / 13 ms |
| 10万 UTF-16 单元多段文 | 108 / 112 ms | 14 / 13 ms |

长文初始化中位数增加约 3.7%，该样本未见明显浏览器性能回归；计时仍包含自动化往返，不覆盖真实 Windows IME、原生桥接或 Markdig，不作为方案中的实机性能门槛达成证据。
