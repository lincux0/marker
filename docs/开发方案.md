# Markdown 编辑与阅读器开发方案

- 文档日期：2026-10-07
- 文档状态：M0 工程基线已实施并完成本机开发签名安装验证；M1 及后续阶段待实施。详细证据见《工程开发指南》。
- 产品定位：Windows 优先、开源、本地文件优先的 Markdown 编辑与阅读器
- 首发架构：C#/.NET 10 + WinUI 3 + Windows App SDK + WebView2 + CodeMirror 6 + Markdig

## 1. 目标与产品原则

产品面向需要长期编辑、阅读 Markdown 文档的 Windows 用户。 首版优先做到稳定打开和保存文件、顺畅中文输入、可靠撤销、快速预览和清晰阅读。 原生应用负责窗口、文件、菜单、设置和系统集成。

CodeMirror 6 负责源码输入、光标、选区、撤销历史和编辑器快捷键。 Markdig 负责把 Markdown 转换为 HTML。 WebView2 负责承载编辑器和预览内容。

应用不要求用户使用云服务或账户。 文档以普通文件保存，用户可使用其他编辑器访问。 默认不修改用户文档中的未知语法。

没有兼容样例或实际需求支撑的语法不承诺首版支持。

## 2. 产品边界与优先级

### P0：首发必须具备

- WinUI 3 原生主窗口和标准 Windows 窗口交互。
- 新建、打开、保存、另存为 Markdown 文件。
- 源码编辑、分栏编辑与预览、独立阅读三种模式。
- CodeMirror 6 编辑能力、中文输入法支持和可靠撤销重做。
- CommonMark 基础语法与明确选定的常用 GFM 语法。
- Markdig 后台解析和 WebView2 预览刷新。
- 标题大纲、查找、替换、状态栏和基本键盘操作。
- 主题与必要的编辑排版设置。
- 未保存状态提示、外部修改检测、恢复草稿和安全保存。
- 本地化应用资源，不从 CDN 加载编辑器或渲染依赖。
- 预览安全边界、最小 WebView2 消息桥接和本地资源限制。
- MSIX 构建、签名方式说明、干净环境安装验证。
- 开源许可证、依赖许可证清单和构建说明。

### P1：首发后完善

- 多标签页、最近文件列表、目录树或工作区浏览。
- 预览与源码按 Markdown 块同步滚动。
- 图片粘贴和受控图片插入，包含资产文件创建与文档保存的失败回滚。
- 数学公式和 Mermaid 图表，明确资源版本与安全策略。
- 外部文件变化的差异查看与用户选择。
- 文档内链接预览与路径导航。
- Windows ARM64 验证与发布。
- 文档模板、导出或打印等由使用反馈确定的能力。

### P2：暂不纳入当前实施

- Typora 式所见即所得或即时排版编辑。
- 云同步、账户、协作编辑、在线分享。
- 插件系统、脚本扩展和第三方主题商店。
- SQLite 文档库、全文索引和知识图谱。
- 自动上传文档或远程 AI 处理。
- 面向所有 Markdown 方言的完全兼容承诺。

进入 P2 的功能需要具体用户场景、数据边界和维护成本评估。

## 3. 技术决策

### 3.1 桌面端

主语言采用 C#，目标框架采用 .NET 10 LTS。 使用 WinUI 3 和稳定版 Windows App SDK；实施时选取稳定版本并锁定兼容的 SDK、Visual Studio 和 .NET 工具链，不在方案中硬编码未经实施确认的最新版本。 依赖升级经过构建、安装、文件操作和 WebView2 回归验证。

不在首版拆分服务进程或插件宿主。

### 3.2 Web 技术层

编辑器采用 CodeMirror 6。 网页层使用 TypeScript 和 CSS，由 Vite 在开发与构建阶段打包；Vite 属于构建依赖，不随应用运行。 CodeMirror 6 通过已安装的官方模块组合扩展，不建立自制编辑器框架。

显式以 Markdown language support 和 base markdownLanguage 配置解析高亮；确认列表、引用等 Markdown 命令按预期启用。 编辑器 WebView2 承载 CodeMirror；预览 WebView2 承载渲染内容。 两个 WebView2 控件共享一个 CoreWebView2Environment。

Environment 生命周期由桌面应用统一管理，并在创建控件前完成初始化。 编辑器和预览分别使用独立 CoreWebView2Controller 与网页上下文。 WebView2 Runtime 使用 Evergreen；安装流程提示或引导缺失运行时的安装。

生产应用不依赖固定版本 Runtime 随应用复制分发。

### 3.3 Markdown

Markdig 在 .NET 侧解析 Markdown。 扩展采用显式白名单配置，避免无意启用额外语义。 前端渲染层仅承担高亮、公式、图表等输出呈现。

最终 HTML 与大纲以 Markdig 的解析结果为准。 CodeMirror 的 Markdown 解析仅服务于高亮与编辑命令，并不是预览渲染器；两者共用兼容样例核对方言差异，不承诺语法树完全一致。

### 3.4 配置与数据

原始 Markdown 文件是文档内容的唯一持久化来源。 设置、窗口状态、最近文件和恢复草稿首版采用 JSON。 JSON 文件包含 schemaVersion，升级时执行有限、可测试的迁移。

首版不引入 SQLite。 当需要复杂查询、索引、数万条元数据或事务关系时再评估 SQLite。

## 4. 应用结构

首版采用一个桌面应用项目、一个 Web 资源项目和一个轻量测试项目。

```text
Marker/
  Marker.sln
  src/
    Marker.App/       # WinUI 3、窗口、文件和应用服务
    Marker.Web/       # Vite、CodeMirror、预览静态资源
  tests/
    Marker.Tests/     # 解析、文档保存、消息协议等核心测试
  docs/
    开发方案.md
```

`Marker.App` 按功能放置少量清晰目录：

```text
App.xaml
MainWindow.xaml
Views/
ViewModels/
Services/
Models/
Assets/
```

`Marker.Web` 按编辑器、预览、共享样式组织源码。 构建时把 Web 产物作为应用资源打包，不运行时下载 npm 包。 避免为单一实现创建通用接口、工厂或插件层。

只有出现第二种真实实现或清晰的测试替换需求时再抽象。

## 5. 模块职责

### 5.1 WinUI 外壳

负责窗口、标题栏、导航、菜单、工具栏、标签和对话框。 负责文件选择器、文件关联、拖放和二次启动文件激活。 负责系统主题、窗口尺寸、屏幕位置和应用设置。

不维护一份独立且可编辑的 Markdown 全文副本。

### 5.2 文档会话

每个打开文档对应一个会话状态。 会话维护路径、磁盘版本信息、编码、换行格式和保存状态。 会话保留最近已接收的编辑器版本号及对应文本快照。

C# 中的文本为传输和保存快照，不是输入过程中的编辑权威。 文档会话负责协调保存、恢复、解析、外部变化和预览请求。

### 5.3 CodeMirror 编辑器

CodeMirror 的当前文档是唯一 live 文本权威。 光标、选区、撤销历史和输入法组合状态始终留在编辑器内。 普通按键输入只在编辑器内部应用，不将全文回写再重设编辑器。

C# 不因每次输入而重置 CodeMirror 文档。 C# 可按节流周期接收文本快照用于保存草稿和解析。

### 5.4 Markdown 预览

C# 接收版本化文本快照并请求 Markdig 解析。 解析在后台执行，避免阻塞 UI 线程。 连续编辑合并解析请求，避免对每个按键启动一次工作。

预览只接受不旧于当前版本的结果。 过期解析完成后直接丢弃，不覆盖较新的预览。 预览 WebView2 常驻加载，通过受限消息更新内容，不每次输入重新导航。

### 5.5 文件服务

负责打开、保存、另存为、编码识别、换行保留和安全写入。 负责监控已打开文件的磁盘变动并通知文档会话。 文件路径和读写权限只存在于原生侧。

## 6. 编辑器与桌面端通信

### 6.1 版本和文本传递

编辑器每次文档事务产生递增版本号。 编辑器发送文本变化时包含文档 ID、版本号、变化范围和替换文本。 变化范围使用 UTF-16 code unit 索引，与 .NET 字符串偏移保持一致。

桥接消息显式声明协议版本，避免网页与桌面版本不匹配时误处理。 初始打开或重新同步时发送完整快照。 正常编辑发送有 baseVersion 的增量 patch。

C# 仅在 baseVersion 与当前快照版本匹配时应用 patch。 版本不匹配时拒绝增量，要求编辑器发送完整快照重新同步。 C# 不把收到的变化反向应用到编辑器，避免双重输入和撤销历史破坏。

### 6.2 输入法与撤销

输入法组合文本期间不由 C# 全文替换或格式化编辑器内容。 本地自动保存不得影响中文候选框、光标和撤销栈。 保存完成仅更新文档的已保存版本，不触发编辑器 reset。

撤销和重做由 CodeMirror 命令执行。 工具栏撤销、重做需检查焦点和编辑器状态后调用对应命令。

### 6.3 协议错误恢复

未知协议版本拒绝处理并记录可诊断错误。 缺字段、超大消息或无效类型不进入业务逻辑。 检测到序号跳跃或 baseVersion 不一致时请求全量快照。

文档切换和关闭时使旧文档的异步消息失效。

### 6.4 保存一致性与协议约束

保存命令向编辑器请求带 requestId 的完整快照，以该响应中的文本和版本执行保存，不直接使用可能落后的节流缓存。 保存期间仍可继续编辑；成功后只标记该快照版本已保存，若当前版本更高，文档继续显示未保存状态。 等待超时、网页崩溃或响应文档不匹配时终止保存并保留恢复数据。

所有增量范围采用同一 baseVersion 文本中的 UTF-16 偏移，区间为左闭右开。 多光标的一组不重叠变更在 C# 按起点倒序应用，避免先前修改移动后续偏移。 重叠、越界或无法验证的 patch 请求全量重同步，不猜测修复。

编辑器和 C# 的活动快照统一采用 LF，保存时根据文件元数据恢复 CRLF 或 LF；不能把磁盘 CRLF 文本直接用于计算编辑器偏移。 打开混合换行文件时记录并提示，首版不承诺逐行保持混合样式；用户明确选择保存换行策略后才允许覆盖。

最小消息类型包括 ready、documentSnapshot、documentChanges、requestSnapshot、executeEditorCommand、previewResult 和 error。 消息携带 protocolVersion、documentId 与 sessionEpoch；异步请求另带 requestId，变更带 baseVersion/version。 页面重建或会话重开递增 sessionEpoch，丢弃旧实例迟到消息。 调用保存、打开链接等有副作用的动作只能由原生 UI 或明确列出的受控命令触发。

## 7. Markdown 语法和兼容策略

### 7.1 首版目标

基线定义为 CommonMark 核心语法。 首版常用 GFM 语法包括表格、任务列表、删除线和自动链接。 支持标题、段落、引用、列表、代码围栏、行内代码、图片和链接。

代码块至少提供纯文本显示，并通过本地语法高亮资源改善常见语言阅读。 标题大纲从同一解析结果生成。 对特殊语法建立文档样例并在发布前验证。

### 7.2 不作出的兼容承诺

“支持 CommonMark 与常用 GFM”不等于 100% GitHub 网页渲染兼容。 GitHub 的扩展、URL 规则、HTML 策略和 GitHub Flavored Markdown 版本可能变化。 首版不承诺 Obsidian 双链、嵌入、Callout 或各类私有方言。

不承诺任意 HTML、脚本、外部插件语法均可执行。 兼容列表记录语法、解析规则、预览结果和已知差异。 对不认识的 Markdown 内容尽量保留原文，避免保存时静默改写。

### 7.3 数学和图表

数学公式与 Mermaid 首发后按 P1 评估。 只有语法识别不够，还需渲染资源、主题和安全审查。 渲染 JS、CSS、字体和语言定义打包在应用中。

公式和图表不可用时展示原文或明确错误占位。

## 8. 预览安全和 WebView2 边界

Markdown 内容视为不可信输入，包括本地打开的文件。 Markdig 负责解析，不负责 HTML 安全净化。 预览 HTML 写入 WebView2 前必须经过净化。

预览采用本地 DOMPurify 作为净化基线，并锁定和审查其版本。 Markdig 输出先作为数据传入预览页面，由净化器处理后才能插入 DOM，不能先插入再清理。 净化规则移除脚本、事件属性、危险 URL scheme 和不需要的嵌入标签。 预览设置严格 CSP，仅允许所需的本地脚本、样式、图片和字体。

禁止使用 CDN、远程脚本和不必要的网络请求。 编辑器桥接只暴露版本化的文本变更、快照、命令和必要状态。 桥接禁止提供任意文件读写、进程启动、Shell、凭据或任意路径 API。

每个消息检查来源、文档 ID、消息大小、协议版本、类型和字段。 WebView2 新窗口请求默认拒绝或交给原生确认后使用系统浏览器。 导航请求采用允许列表；预览内容不得导航到任意本地文件或远程页面。

使用虚拟主机名映射应用内静态资源，避免直接暴露文件系统目录。 文档图片仅允许来自当前文档目录及其受控子目录。 图片路径规范化后检查实际解析路径仍在允许根目录内。

拒绝路径穿越、危险协议和不受控绝对路径。 不只比较路径字符串前缀，还要处理符号链接、目录联接和重解析点造成的越界；首版可直接拒绝经过重解析点的资源。 应用脚本与文档资源采用不同来源，文档资源禁用跨域读取和脚本执行，不把文档目录映射成有桥接权限的应用页面。 远程图片默认不加载，用户启用后仍受网络与协议规则约束。

后续加入 Mermaid 时使用严格安全配置，禁止图表中的脚本、交互回调和任意导航。 公式、图表等依赖生成的 HTML/SVG 必须检查最终输出，不能认为先前净化过的输入可在任意后处理后保持安全。 预览跨域、存储和本地资源访问策略需在原型中验证并写入安全测试。

## 9. 文件安全与恢复

### 9.1 编码和换行

打开文件时识别 UTF-8、UTF-8 BOM 和常见 Windows 编码策略。 无法可靠判断的编码提示用户选择，不静默替换字符。 保留原文件是否有 BOM 的信息。

保留 CRLF 或 LF 换行风格。 新文件默认 UTF-8、无 BOM、LF，用户可在设置中更改。 保存时不对 Markdown 文本自动重排或格式化。

### 9.2 安全保存

保存先写入目标目录的临时文件，再执行原子替换或安全移动。 写入成功并确认替换后才更新已保存版本和磁盘状态。 替换失败时保留原文件并向用户报告，不清除恢复草稿。

另存为保持目标已确认后才切换文档路径。 文档含相对图片链接时，跨目录另存为需由用户选择复制资产并改写相对路径，或保留原引用并说明可能失效；先复制到临时资产位置，再完成文档写入，失败时清理未提交的新资产。 保存操作应处理只读文件、权限不足、磁盘空间不足和文件占用。

### 9.3 外部修改冲突

打开时记录可用于比较的磁盘指纹和最后写入时间。 保存前再次检查目标是否被外部修改。 发生外部变化时暂停覆盖并提供重新加载、另存副本或继续覆盖的选择。

选择继续覆盖需明确确认，不能静默丢弃外部编辑。 多标签打开同一文件时复用同一文档会话，避免两个编辑器互相覆盖。

FileSystemWatcher 仅作为变化提示，不能作为唯一冲突依据；保存前复核磁盘内容指纹。 无法可靠排除并发变化时提示另存副本，不承诺仅靠“检查时间戳再替换”就能避免所有竞态。 同一会话的保存请求串行执行，避免较旧的保存结果覆盖较新内容。

### 9.4 恢复草稿和关闭

恢复草稿独立于原始文档保存，带文档 ID、版本号、更新时间和原文件路径。 草稿写入做节流，退出和崩溃恢复路径均保持原文件安全。 启动时发现恢复草稿，显示可恢复提示并允许查看差异。

关闭窗口遇到未保存内容时可保存、放弃或取消关闭。 正常关闭后按策略清理已确认不再需要的草稿。 恢复文件不在用户未确认时覆盖原文档。

## 10. 界面与交互

### 10.1 主界面

采用原生标题栏、标签区域、文档工作区和状态栏。 左侧导航可折叠，首版不强制常驻复杂文件树。 主体支持源码、分栏、阅读三种模式。

模式切换保留光标位置、选区、滚动位置和当前文档。 标题大纲可按需打开，不占用狭窄窗口的主要写作空间。

### 10.2 模式定义

源码模式显示 Markdown 原始文本并由 CodeMirror 编辑。 分栏模式左侧编辑、右侧预览。 阅读模式隐藏编辑控件，显示排版后的文档。

阅读模式为只读；切回编辑时恢复原状态。 首版不实现 Typora 式边输入边隐藏标记的即时排版。

### 10.3 视觉风格

遵循 Fluent 2 的层级、间距、控件状态和图标原则。 标题栏可使用 Mica 或 Mica Alt。 Mica 不用作长文正文的主要背景。

透明效果不可用、关闭或系统资源受限时回退到实色表面。 编辑区和预览区主题保持一致，但各自允许设置文字宽度与行高。 深色模式、浅色模式和跟随系统至少有清晰行为。

高对比模式遵循系统颜色并避免仅用颜色传达状态。

### 10.4 动效与可访问性

优先使用 WinUI 控件已有过渡与状态动画。 Composition 仅用于原生控件难以表达且能改善反馈的少量动效。 动效短、可预测，不延迟输入、滚动、保存和窗口操作。

响应系统减少动态效果偏好。 支持键盘完整操作、焦点可见和合理 Tab 顺序。 WebView2 内编辑器提供可访问标签、快捷键和屏幕阅读器语义。

验证 WebView2 获得焦点时的 WinUI 原生浮层、菜单和提示是否被网页合成层遮挡；必要的浮层放在 WebView 内或通过窗口级方案实现。 高 DPI、窗口缩放和多显示器迁移时布局不截断。

## 11. 性能与降级

性能目标是待原型验证的候选门槛，不代表当前已测结果。 小型文档候选规模：不超过 1 MiB。 小型文档从打开到可编辑的目标候选值：冷启动后 2 秒以内。

输入到预览稳定更新的目标候选值：常见文档中位数 150 ms 以内。 候选交互帧率目标为常见设备上滚动接近 60 FPS。 必须在低配 Windows 设备、长文档和多标签情况下实测内存与响应。

性能数字应记录设备、文件规模、运行时和测试方法。 单个页面包含超大代码块或大量图片时也要测量。 解析按版本和节流调度，丢弃过期结果。

大文档可降低预览刷新频率或暂停图片解码，但不得破坏文本保存。 可在设置中提供“输入时暂停预览”或自动降级提示。 可视区域外的大量图片采用懒加载。

超出候选阈值时提示用户，并允许关闭预览继续安全编辑。 禁止因性能降级而裁剪、改写或丢失 Markdown 文本。

### 11.1 滚动同步

同步滚动不按两个视图的滚动百分比粗略映射。 Markdig AST 生成标题与块级节点的源码范围。 编辑器通过源码偏移定位当前块。

预览节点映射到同一源码范围，按最近的稳定块定位。 解析结果过期、节点映射缺失时暂停精确同步并保持视图可用。 P0 可先提供点击标题跳转，连续双向同步列为 P1。

## 12. 设置和会话 JSON

设置文件保存主题、字体、字号、行高、阅读宽度、预览选项和最后窗口状态。 会话文件保存最近打开文档、标签顺序和上次工作区状态。 恢复草稿使用独立文件，避免设置损坏影响文档恢复。

所有文件包含 schemaVersion、写入时间和应用版本。 读取损坏配置时保留原文件副本并恢复默认设置。 迁移只处理已发布 schema 版本，不猜测任意未知字段含义。

不在 JSON 存储文档全文索引或大规模缓存。 当查询、事务和数据量需求明确后再引入 SQLite。

## 13. Windows 支持与分发

首发支持范围按 Windows 版本仍处于 Microsoft 支持期与依赖支持期的交集确定。 初步以受支持的 Windows 11 x64 桌面版本为首发验收范围。 在发布计划中明确具体最低系统版本，并随支持生命周期更新。

Windows 10 仅在用户需求和依赖兼容性验证后决定是否支持。 首发架构为 x64；ARM64 在单独构建和设备实测后加入。 验证不同 DPI、多个显示器、系统主题、高对比度和系统缩放。

验证文件关联、拖放、多实例文件激活和安装升级。 MSIX 作为安装包格式。 发布前决定 Microsoft Store 或站外分发渠道。

MSIX 发布构建必须签名；证书信任和更新方式按渠道落实。 开发证书只用于本机开发与测试，不作为公开发布凭证。 Evergreen WebView2 Runtime 安装和缺失提示纳入干净机器测试。

自动更新由 Store 管理或由后续独立更新方案管理，不首版自制更新服务。

应用代码许可证已由维护者确认为 MIT，许可证决策及正式发布合规由维护者负责；当前仍为私有开发仓库。 第三方依赖分别遵守其自身许可证，不因应用采用 MIT 而改变。 发布时提供第三方组件和许可证清单。

### 14.1 构建与发布流程

开发环境使用支持所选 .NET 10 与 WinUI 工具链的 Visual Studio、Windows SDK、Node.js LTS 和 npm。 npm 锁文件与 NuGet 版本纳入 Git，Web 资源构建输出打包进 MSIX；用户机器不需要 Node.js 或开发服务器。

CI 在 Windows runner 上依次执行依赖恢复、Web 类型检查与生产构建、核心逻辑测试、桌面 Release 构建及未签名 MSIX 产物生成。 正式发布流程独立完成签名与安装验收，凭据存入受保护的发布环境，不写入仓库或日志。 产物记录版本、架构、提交号、依赖清单和 SHA-256。 桌面交互、IME 和安装验收仍需真实 Windows 会话，不能以普通 CI 构建代替。

应用版本、包版本和网页桥接协议版本分别管理。 安装升级保留设置与恢复数据，删除旧版本配置前先完成迁移与验收。 卸载应用不删除用户文档；应用私有数据能否跨卸载保留按 MSIX 行为验证，并提供显式导出设置或恢复草稿的方式。

日志只记录版本、错误类型、耗时和必要的匿名标识，默认不记录文档正文、完整用户路径或剪贴板内容。 首版不自动上传日志或遥测，故障报告由用户主动导出。

## 15. 测试策略

### 15.1 核心逻辑

Markdig 解析样例覆盖标题、嵌套列表、转义表格、任务列表、HTML 和链接。 版本化 patch 测试覆盖正常顺序、重复版本、版本跳跃和全量重同步。 UTF-16 偏移测试包含中文、emoji、代理对和组合字符。

保存测试覆盖 BOM、UTF-8、CRLF、原子替换和失败恢复。 JSON 测试覆盖当前 schema、升级迁移、损坏和未知版本。

### 15.2 WebView2 和编辑体验

验证两个控件共用 Environment，关闭时控制器和进程可正常释放。 验证中文 IME 组合、候选框定位、撤销重做和焦点切换。 验证编辑器初始化失败、Runtime 缺失和重新加载后的恢复流程。

验证高频输入期间预览版本单调前进，不出现旧内容覆盖新内容。 验证搜索替换、模式切换和多标签文档状态互不污染。

### 15.3 安全测试

输入脚本标签、事件处理属性、危险 URL 和恶意 SVG 样例。 验证预览净化后不执行脚本或任意事件代码。 验证路径穿越和指向文档根目录外的图片均被拒绝。

验证 bridge 拒绝未知来源、未知协议、超大消息和未授权操作。 验证预览新窗口和远程导航不会绕过应用策略。

### 15.4 文件和系统测试

覆盖新建、打开、另存为、只读、权限不足和目标被占用。 覆盖外部程序修改、删除、重命名和并发保存冲突。 覆盖异常退出、重启恢复、取消关闭和草稿清理。

覆盖文件拖入、文件关联、二次启动和多显示器窗口恢复。 覆盖深浅主题、高对比度、减少动画、高 DPI 和缩放变化。

### 15.5 发布测试矩阵

系统版本以发布时支持清单为准，并记录精确版本号。 设备至少覆盖常规性能设备和一台低配设备。 架构首发覆盖 x64；ARM64 发布时增加 ARM64 设备验证。

分发验证覆盖干净安装、升级安装、卸载和已安装 WebView2 Runtime。 测试结果标记为通过、失败、未执行或受环境阻塞，不混写成已验证。

## 16. 开发里程碑

阶段任务按实际结果勾选，M0 的本机验证与远端 CI 状态分别记录在《工程开发指南》中。阶段按单主开发者的顺序设计；少量互不依赖的文档、许可证盘点或 CI 工作可以并行，但安全和文件闭环是进入完整功能开发的前置门槛。任务勾选不代表尚未执行的远端运行或正式发布已经完成。

|---|---|---|---:|

按单主开发者全职投入、每周 5 个工作日估算，M0–M5 首发合计约 32–48 个工作日；加入 20%–30% 缓冲后约 39–63 个工作日，即约 8–13 个工作周。M6 不计入首发工期，也不承诺在一个小型迭代内完成全部 P1。此范围是早期排期估算，不是期限承诺；不含 Store 审核、证书申请等外部等待，学习工具链、实际设备验证与尚未实测的性能问题均可能扩大范围。每阶段结束后按实际结果更新剩余估算。

## 17. 首版验收标准

用户可以从文件资源管理器打开 Markdown 文件。 用户可以创建、编辑、保存和另存为 `.md` 文件。 中文输入、撤销、重做和焦点切换通过目标设备实测。

编辑器和预览保持同一版本顺序，旧结果不会覆盖新结果。 三种模式切换不会丢失文档、光标和主要阅读位置。 明确列出的 CommonMark 与常用 GFM 样例通过检查。

未列出的方言行为不作为兼容验收承诺。 外部修改和未保存关闭都有明确用户决策路径。 恢复草稿不会未经确认覆盖原始文件。

危险 HTML、URL、桥接消息和图片路径测试满足安全预期。 UI 支持目标系统主题、DPI、键盘操作和高对比模式。 MSIX 在目标系统干净安装；签名和 Runtime 状态可验证。

性能验收报告标注实际设备和文档规模，不以候选数字冒充已完成测量。

## 18. 风险与应对

WebView2 与 WinUI 混合输入的复杂度高，尤其是中文 IME 和焦点。 尽早用真实输入法验证原型，不把此项留到发布前。 全量文本快照若过于频繁会增加跨进程复制和解析负担。

用版本化增量、节流快照和可触发全量重同步控制复杂度。 Markdown 原始 HTML 和本地图片扩大预览攻击面。 默认净化、限制导航和资源根目录，并把安全测试作为验收项。

不同 Markdown 工具链的扩展语义不一致。 公布兼容清单和已知差异，避免使用“完全兼容”表述。 MSIX 站外安装涉及证书信任和用户安装体验。

在产品代码成形前确定分发路径和签名可行性。 双 WebView2 会增加内存占用。 原型实测后决定是否延迟创建阅读预览或在单视图模式释放不需要的页面。

性能优化须基于目标设备测量，不以猜测提前引入复杂缓存。
