- 调查基线：提交 `2dfac07`，结合当前源码、[架构基线](architecture.md)、[技术决策](decision.md)、[工程开发指南](工程开发指南.md)与[项目历程](progress.md)。
- 输入：[用户提供的 ChatGPT 分享方案](https://chatgpt.com/share/6ac8c75a-b5ec-83ec-9cf3-99fc04ff9611)。Exa 抓取为空，后经浏览器读取完整正文，并由 Jina Reader 交叉读取；正文已纳入分析。
- 范围：当前正文视图的视觉、Markdown 组件与阅读交互，以及后续专业语法的可行实施路径。初版交付为文档，现已实施 U0–U1；U2 及后续阶段尚未实施。

## 1. 推荐结论与目标

以“清晰的中文长文排版 + 克制的 Windows 浮动操作层”为主方向。第一轮直接改善当前单页即时呈现界面，不恢复历史三模式、不更换 CodeMirror、不改文件保存与恢复链路。先改善标题、段落、表格、代码、引用、图片的一致性，再增加目录和锚点；公式、图表等需要新解析或依赖的能力分别进入后续阶段。

将“阅读界面”区分为两个实施对象：

1. **当前可见正文界面**：CodeMirror 6 装饰后的可编辑 Markdown，是本轮默认优化对象。
2. **可选纯阅读视图**：Markdig HTML 预览成为可见只读页面，适合完整 HTML 表格与语义化读屏；对应解析和渲染扩展实施后也可承载公式、图表。它会改变 D016 的交互约定，必须在实施前取得用户明确选择，不能借 UI 优化直接恢复旧阅读模式。

目标是让长文内容易扫读、中文混排舒服、复杂内容不撑破页面、普通操作可用键盘完成，并保留原始文本和撤销历史。视觉改进不得以丢字、输入法错位、光标漂移或扩大资源访问权限为代价。

### 1.1 范围边界

本方案不引入账户、云同步、AI 上传、文件树、多标签、插件系统或主题商店。排序表格、代码执行、可点击 Mermaid 节点、任意 HTML/SVG 文档输入、导出与打印不属于首轮。

所有尺寸和新组件规则为建议验收目标；不是已实现状态，也不是规范规定的唯一最佳数值。现有用户字体、字号、行高、主题、配色和工具栏偏好优先。

## 2. 项目现状与真实问题

### 2.1 当前结构

Win32 主窗口拥有两个原生 windowed WebView2：编辑页填满客户区，预览页隐藏为 1×1；XAML Island 也隐藏，仅保留兼容字段。可见工具栏与正文位于同一编辑 WebView，设置仍为独立 WinUI owned 窗口。不能把 XAML 浮层直接叠到 WebView 正文上，忽略 HWND 空间限制。

| 模块 | 当前能力 | 对优化的约束 |
|---|---|---|
| `main.ts` / `live-markdown.ts` | 单一 EditorView、装饰、源码开关、选区、撤销、IME 保护 | 保留实例和事务；不能把 DOM 当文档数据 |
| `toolbar.ts` / `style.css` | 浮动工具栏、更多菜单、本地统计、可配置直显项 | 设置入口常驻；隐藏项与快捷键仍可访问 |
| `MarkdownRenderer.cs` | 同一 Markdig AST 输出 HTML、标题 ID 与 UTF-16 偏移 | Markdig 为 HTML/大纲权威；不与 CodeMirror AST 混用坐标 |
| `preview.ts` / `preview.css` | 净化 HTML、目录、JS/TS 围栏高亮、主题与滚动保留 | 当前不可见；已有样式不等于用户已获得阅读功能 |
| `AppSettings.cs` / `SettingsDatabase.cs` | SQLite 设置持久化、字段验证、损坏/未来版本保护 | 新设置须覆盖两端校验、序列化、旧值回退和测试 |
| `LocalImageResources.cs` / `links.ts` | 受控本地图片、Ctrl+点击链接、原生打开流程 | 不允许远程图片、任意磁盘路径或页面直接导航 |

### 2.2 参数基线

当前可见纸面最大外宽 **980 CSS px**，宽屏横向内边距最多 76 px，因此文字区约 **828 px**；工具栏常规宽度 **1108 px**，顶部偏移 14 px，最小高度 50 px，按钮 36×36 px。纸面圆角 18 px、工具栏圆角 16 px，玻璃使用 32 px blur 与 1.5 倍饱和度。这里的 980 是纸面宽，不能直接与分享方案的“正文宽 820”当成同一个量比较。

生产 `AppSettings.Default` 为 **16 px / 1.5 行高 / 0.5em 段距**；前端初始化 fallback 为 15 px / 1.5，CSS 无设置时为 15 px / 1.65。进入生产后以宿主有效设置为准，不能把 CSS fallback 写成应用默认值。正文默认系统字体，H1/H2 默认宋体候选栈，已有五种配色。

### 2.3 已能从源码确认的问题

- 当前宽屏中文文字区在 16 px 时约容纳 50 多个全角字，长段落回行距离偏长；尚无用户可调文字宽度。
- 表格以 CodeMirror 行及等宽 inline-block 单元格呈现，带纵向分隔；列数多时窄列会连续换行。它不是完整的 HTML 数据表格。
- 图片普遍使用 12 px 圆角和阴影，技术截图、透明图也受相同处理；失效图片反馈与后台预览的移除行为不一致。
- 可见正文没有有效目录入口与页内锚点导航；后台已有 Markdig 大纲不能直接算作完成。
- 可见代码块已有基础容器和语言标记，但不能推定所有语言均高亮；隐藏预览仅复用 JS/TS 解析器。
- 数学、脚注、提示框、Mermaid 未在当前 Markdig pipeline 启用。装饰层能识别部分额外强调节点，不代表两个解析器已经同义支持。

以上是方案初版的实现分析。后续 U0–U1 已启动真实 EXE、截图审查并采集浏览器性能数据，结果见验收记录；阅读舒适度尚无用户研究结论。

## 3. 分享方案的采纳与修正

下面是对分享方案的简要归纳，详细规则由本项目约束重新设计。

| 分享建议 | 本项目处理 |
|---|---|
| 文字建立层次，复杂块独立呈现 | 采纳；不为每段增设卡片 |
| 820 px、17 px、1.8 的基础排版 | 作为候选样张；不覆盖已保存偏好 |
| 一套共享主题变量 | 采纳；复用已有配色，不再建立三套主题体系 |
| 表格、代码加强结构和操作 | 分阶段；先保真与溢出，再复制和查看 |
| Shiki 专业代码高亮 | 条件采纳；首轮复用现有解析器 |
| KaTeX / Mermaid | 后续独立能力，需要依赖、安全与性能门槛 |
| 悬停出现辅助操作 | 同时支持聚焦和触屏，不以悬停为唯一入口 |
| 大纲与分屏同步 | 优先可见目录；分屏不纳入当前默认路线 |
| HTML、SVG 与扩展语法 | 保留禁止原始 HTML 与受控图片规则，逐项评估 |

需要修正的语义：GitHub 的提示框是其 Markdown 扩展，不能简单称为核心 GFM 标准能力；Markdig 支持某扩展不等于当前 pipeline 启用，更不等于 CodeMirror 能编辑呈现；Markdig 不是 HTML 净化器；暖纸效果已有 `paper` 配色可供评估，无需新增独立 Sepia 主题。语法解析和图形/公式渲染是不同步骤。

## 4. 视觉系统与布局

### 4.1 视觉方向

保留现有品牌图标、纸面和浮动栏轮廓。主次关系为正文 > 标题/复杂内容 > 导航 > 操作按钮。强调色用于链接、选中和焦点，不让所有标题彩色化；图片、正文、普通公式不统一加卡片阴影。

UI 字体与文档字体继续分工：系统控件采用系统字栈；正文及 H1/H2 尊重已有设置；代码采用 `Cascadia Code, Consolas, monospace` 本地回退，不在线加载字体。宋体标题的字重由真实字形表现决定，避免依赖不存在的 650 字重。Fluent 的字号阶梯适用于界面控件，本项目长文字号需独立评估。[Fluent Typography](https://fluent2.microsoft.design/typography)

### 4.2 版心与响应式

| 场景 | 建议布局 | 行为 |
|---|---|---|
| 普通宽窗 | 保留 980 px 外纸面；新增约 720 px 的正文宽度候选，680–760 px 样张比较 | 16–18 px 中文约 38–45 字/行；这是产品目标，不是硬性标准 |
| 默认 960 DIP 窗口 | 纸面随可用客户区缩小，横内边距 32–48 CSS px | 不为了目录挤压正文 |
| 720 DIP 最小窗 | 维持纸面宽度保护；横内边距 20–24 CSS px，辅助操作进更多 | 不出现单字列或整页横滚 |
| 更窄 Web 重排检查 | 文本容器可缩至 320 CSS px 等效宽度，内边距可进一步到 12–16 px | 用于缩放验收，不代表修改原生最小窗 |
| 超宽窗 | 正文停止增长，留白居中；可选目录仅在空间足够时常驻 | 不拉伸标题和代码到整个屏幕 |

首轮先提供同一内容的“保持当前文字宽度”和“舒适文字宽度”视觉对照，避免同时把字体、字号和配色全部改掉。若新增宽度设置，建议只有“舒适/宽”两档：舒适限制内文字区，宽保留当前纸面内可用宽度；旧设置缺省为宽，用户选择后才持久化。数值和是否新增档位列为实施前待确认项。

在 CodeMirror 中不能随意给所有 `.cm-line` 单独加 `max-width`：表格、选区与光标坐标可能失配。先验证统一内容盒子与测量，再决定宽块的实现；不要用负边距制造未经测量的“突破版心”。纯 HTML 阅读页才适合正文限宽、宽表格单独占满纸面。

### 4.3 设计变量

在已有 `--editor-*`、`--preview-*` 和 `WritingPalette` 上添加必要语义，首轮不抽象成新主题引擎。共享规则可在第二个使用点明确需要时放入本地公共 CSS；颜色仍来自现有主题，禁止新蓝色方案覆盖用户配色。

| 语义 | 建议规则 |
|---|---|
| canvas / surface / text / muted / border / accent / focus | 映射已有画布、纸面、正文、次要文字、边框、强调和焦点变量 |
| surface-subtle | 从纸面与配色混合产生代码、表头背景；分别测浅色和深色 |
| note / tip / important / warning / caution | 仅提示框使用；图标与文字标签同时表达语义 |
| 间距 | 界面用 4/8/12/16/24/32 px；正文间距优先 em，随字号缩放 |
| 圆角 | 行内代码 4 px；内容块 10–12 px；图片 0–8 px；保留纸面与工具栏当前外轮廓 |
| 动效 | 颜色/透明度 120–160 ms；不动画正文高度与字号；减少动画时取消非必要过渡 |

正文保持不透明表面。保留用户已选择的浮动玻璃栏，但按其最不利背景测量文字和焦点对比度。菜单以可读性优先，不能因为材质建议降低安全通知辨识度。Fluent 对不同材质有具体用途区分，本项目 Web CSS 模糊也不等于原生 Acrylic。[Fluent Material](https://fluent2.microsoft.design/material)

## 5. 各语法组件规范

### 5.1 标题与正文

标题倍率统一，以实际正文设置计算；保留 H1/H2 字体选择。候选阶梯如下，16 px 正文时相应约为 32/27/23/20/18/16 px。

| 元素 | 字号/字重 | 上/下间距 | 规则 |
|---|---|---|---|
| H1 | 2em / 700 | 1.4em / 0.65em | 文首减少上间距；不自动居中，不强制只允许一个 H1 |
| H2 | 1.7em / 650–700 | 1.4em / 0.55em | 章节主要层级，不默认加彩条 |
| H3 | 1.45em / 600–650 | 1.25em / 0.5em | 清楚区分正文 |
| H4 | 1.25em / 600 | 1.1em / 0.4em | 不额外容器化 |
| H5 | 1.1em / 600 | 1em / 0.4em | 依靠字重保持辨识 |
| H6 | 1em / 600 | 1em / 0.4em | 可弱化但文字对比度仍需达标 |
| 正文 | 已有用户字号/行高 | 段距尊重设置 | 17 px / 1.7 / 0.75em 仅作为舒适样张候选 |

CodeMirror 标题保留用行盒 padding 的工程约定，不机械改成 HTML margin；配置变更后要求重新测量，检查点击位置与光标一致。HTML 预览可以使用 margin，但须避免文首空白叠加。

中文采用自然左对齐，不自动插入实际空格、不改源文标点，不强制首行缩进和两端对齐。文本 URL 可以局部断行；代码和公式遵循各自规则。中英、数字、全角标点、emoji、宋体回退需专门样张比较。中文排版资料用于检查标点禁则和混排，不将出版物的版面规则全部强加给编辑器。[W3C 中文排版需求](https://www.w3.org/TR/clreq/)

行内语法：加粗保持正文色；斜体保留作者语义，不替换成颜色；删除线仍可辨认；行内代码 0.1em/0.3em 轻内边距、4 px 圆角、约 0.9em 字号。长行内代码允许视觉换行但复制保留文本。链接始终可辨识，聚焦清晰；编辑界面的 Ctrl+点击手势不改。

软换行与硬换行须形成明确兼容样例；CodeMirror 源码行展示和 Markdig HTML 段落流不一定相同，不能仅靠隐藏标记宣称完全一致。HTML 实体、转义、参考式链接与嵌套强调均保留文字信息。

### 5.2 列表与任务清单

无序列表层级以标记和缩进表达，每层约 1.25–1.5em；有序列表保留起始编号，测试 9→10 与 99→100、不连续编号和嵌套引用。紧列表不增设段距，松列表尊重段落结构；不要把源码缩进的空格既保留又再次叠加 CSS 缩进。

任务复选框以对齐和状态清楚为先；当前可编辑界面保留点击/Space/Enter 的 CodeMirror 事务更新及撤销。若启用纯阅读视图，默认仅显示状态，点击不改文档。交互阅读勾选是单独待决功能，绝不能只改 DOM 或直接写磁盘。

### 5.3 表格

先做表头与横向分隔清晰、纵向线减弱、单元格 0.5–0.65em 内边距，单行自然约 40–44 px，多行自动增高；正文不截断成省略号。严格保留左/中/右对齐与转义竖线。

**当前编辑页**：等宽单元格实现先保持结构，优化色彩、间距和选区。列宽分配、整体横滚、复制 TSV 不是 CSS 一改就完成：须从解析得到单元格边界，支持鼠标定位、键盘跨列、IME、范围选择和撤销后再升级。首轮不为了 HTML 观感将整张可编辑表格替换成不可编辑 widget。

**可选 HTML 阅读页**：使用语义化 `table/thead/th/tbody`，表格外 wrapper 局部 `overflow-x:auto`，表格最小列宽约 7–10em 并尊重内容。焦点进入滚动区后可键盘滚动；宽表显示“可横向滚动”提示。复制表格默认保留 TSV 内容与换行，显示成功或失败；展开查看先用本页对话层，关闭返回原焦点。

不默认加排序、筛选、编辑单元格、斑马纹或每行强烈 hover。密集表格预设暂缓；通过原有字号和内容自然高度解决大部分差异。

### 5.4 代码块

独立轻背景、1 px 柔边框、10–12 px 圆角；语言标签与复制按钮在 32–36 px 操作条内，未知语言显示文本标签，不能虚构文件名。代码字号建议 14 px 或正文 0.875em，行高 1.6，等宽字体本地回退；复制只复制原始代码，不包含行号、语言或反馈文案。

阅读页默认保留代码空格与换行，横滚局限于代码区。编辑页继续尊重现有自动换行设置，不用阅读规则改变用户编辑行为。行号、指定行高亮、块折叠暂缓；长代码默认完整可达，任何折叠都必须有键盘展开入口且不改变复制结果。

优先复用已安装的 JS/TS 解析器。若 C#、Python、JSON、Shell 等确有高亮需求，再对比扩展现有 Lezer 与 Shiki：前者接入少、与编辑风格一致；后者语言覆盖广，但带来额外语法资源、启动和内存成本。采纳 Shiki 时仅打包批准语言和明暗两套主题，单例复用、离线资源；不能把浏览器的动态导入理解为没有安装包体积成本。[Shiki Bundles](https://shiki.style/guide/bundles)

双主题应由应用主题切换控制，强制配色优先覆盖 token 色；不跟随系统媒体查询而忽略用户明暗设置。生成样式需兼容 CSP 与净化策略，不能放开任意用户内联样式。[Shiki Dual Themes](https://shiki.style/guide/dual-themes)

### 5.5 引用与提示框

普通引用使用 2–3 px 中性竖线、约 1em 缩进，背景透明或极淡；保留原字形和列表，不默认斜体化全文，不自动推断署名。嵌套引用最多强化结构，不无限增加颜色。

提示框属于待新增解析能力。若采用 `[!NOTE]` 等，分别支持 Note、Tip、Important、Warning、Caution：语义图标 + 中文标签 + 轻背景，正文仍用可读色。未知标签保持普通引用；嵌套与多段内容按 AST 处理，禁止对整篇 Markdown 做正则替换。是否启用、首轮五种还是部分种类均应在开发前确认。[Markdig 扩展](https://xoofx.github.io/markdig/docs/extensions/)

### 5.6 图片与失效资源

保持比例、最大宽度 100%，小图不放大；普通展示最大高度约 70–75vh。技术截图默认无阴影；透明图不强制白底，不裁切内容；6–8 px 圆角仅用于适合的图片，用户提供的图不改写。

alt 是替代文本，不等同于 caption。首轮不要自动把全部 alt 重复显示成图片说明；需要 caption 时采用已确认的文档语法。失败时显示“图片不可用”与安全的相对名称/替代文字，重试仍走同一资源校验；不可泄漏绝对路径或将拒绝资源自动变成远程请求。后台当前直接移除不可解析图片，后续应在 renderer 返回安全占位信息并补测试，不能只在 CSS 中修补。

灯箱列入后续：在当前 WebView 内显示，适配/原尺寸切换、可见关闭按钮、Esc、焦点约束与恢复；缩放可用按钮和键盘，滚轮不劫持普通正文滚动。带链接图片优先遵守链接动作，放大入口另行提供，避免同一次点击触发两个操作。GIF 不承诺暂停；默认 SVG 文件仍拒绝，不因支持 Mermaid 生成图而允许任意 SVG 输入。

### 5.7 公式

候选语法 `$...$` 与独占行 `$$...$$`，先验证货币、转义美元、代码、链接和跨行边界，不能全页自动扫描所有美元符号。Markdig 负责 math AST，KaTeX 负责显示；两个视图共用原始公式，不从生成 HTML 反推源码。

行内公式跟正文基线，不加卡片；复杂分式允许必要行盒增高，不能靠固定高度裁切。块公式居中、上下约 1.25–1.75em，无默认边框，长公式局部横滚。复制使用原始 LaTeX；错误显示源公式与简短说明，其他正文照常显示。

KaTeX 候选配置为 `trust:false`、`output:'htmlAndMathml'`，严格模式与错误捕获明确配置；倾向捕获渲染错误后用 `textContent` 显示源码，避免仅红色提示。限制长度与宏展开，宏不跨文档共享；CSS/字体本地打包，保留 MathML 与 HTML 所需的净化白名单并专项验证。Context7 已核实相关选项；最新文档不能当作已安装版本，本仓库目前未依赖 KaTeX。[KaTeX Options](https://katex.org/docs/options.html)、[错误处理](https://katex.org/docs/error.html)

在编辑页采用 widget 时，公式内光标进入应显示可编辑源语法；源码模式完整保留。必须按 CodeMirror 直接 decorations 的规则处理影响高度的替换，而不是在 viewport 插件中引入块高度变化。若坐标/IME/选择无法稳定，先保持源码，等待纯阅读路线决定。[CodeMirror Decorations](https://codemirror.net/docs/ref/#view.EditorView^decorations)

### 5.8 Mermaid

只识别明确的 `mermaid` 围栏；首批支持流程图和时序图样例，其他图类型不预先承诺。图表在轻背景或透明表面展示，文字随主题可读，图内配色克制；大图先适配宽度，独立查看层再提供缩放/平移。失败和超限保留完整源码，不留空白框。

`securityLevel:'strict'`、`startOnLoad:false` 是起点，不是完整安全保证。应用固定配置，文档 directives/front matter 不能覆写安全与任意 CSS；限制图文本和复杂度，串行或有界渲染，版本过期结果丢弃。生成 SVG 需要专门净化配置，禁止脚本、事件、外部资源和不受控链接；若净化破坏图类型，降级源码而非放宽整页权限。Mermaid 的 SVG 是生成产物，不能复用成任意文件 SVG 通道。[Mermaid Security Configuration](https://mermaid.js.org/config/schema-docs/config-properties-securitylevel.html)

Context7 返回部分测试样例含攻击载荷，只用作风险验证线索，不能复制其直接 `innerHTML` 插入方式。导出 SVG/PNG、节点点击、图表修改与执行均暂缓。

| 语法 | 状态与目标 |

| 定义列表 | 待需求确认；术语字重、解释缩进，无新卡片 |

## 6. 全局阅读交互

### 6.1 工具栏

保持 1108/980 px 的当前外宽关系及用户直显偏好；不根据旧历史记忆退回 1012 px。先检查标题可用宽度、错误通知、菜单触达和统计稳定性。字数统计沿用现有口径，不因视觉改造把代码或表格从计数中移除。

后续“专注”作为会话级 UI 状态，隐藏可选操作但保留清晰退出、设置与错误通知；不另建持久化系统，不覆盖隐藏按钮偏好。默认不滚动自动消失，避免用户寻找保存按钮。源码开关继续叫代码/源码显示，不改名为纯阅读，以免混淆。

### 6.2 大纲、锚点和定位

优先复用 Markdig 已有唯一标题 ID 和偏移。点击目录项在当前 EditorView 定位，保留撤销，不触发编辑命令；重复标题、空标题、emoji、层级跳跃都需校验。offset 是 UTF-16，必须绑定当前文档版本，过期位置不能直接使用。

布局建议：有足够空间时右侧约 220–240 px 目录，正文与目录约 24 px 间隔；可用宽度不足以保留至少约 640 px 纸面时退回浮层。目录默认收起，长目录自身滚动，折叠入口可键盘访问。滚动高亮可对源行可见位置计算，不假设 CodeMirror 虚拟 DOM 中存在所有标题；超多标题只渲染必要目录行。

页内 `#anchor` 应优先作为文档导航处理，不能交系统打开；保留 Markdig ID 规则并测试 URI 编码。复制章节链接在已保存文档与未命名文档中定义不同文案，不虚构可分享 URL；第一版可仅支持复制锚点。若点击目录会改变编辑选区，应记录并提供合理返回位置。

固定栏下的目标行、查找命中和键盘焦点必须可见；滚动定位需要实际 toolbar 高度加安全间距，不能仅硬编码 50 px。原生焦点、Web 浮层与设置窗口关闭恢复分别验证。

### 6.3 可选纯阅读路线

若用户确认需要独立只读页面，优先评估复用现有 Markdig preview WebView，切换时保留同一 EditorView 实例、最新文档版本、源位置和滚动锚点；不恢复三模式/分屏。阅读工具栏必须与阅读正文同一 HWND：可在 preview 页装配现有 toolbar 的适用部分，不用 XAML 覆盖。

纯阅读使用真实标题、列表和表格 DOM，任务只读、普通点击导航；文件操作仍调用原生已有命令。返回编辑恢复最近选区和撤销历史；切换时拒绝打断未提交 IME。读取未完成渲染需显示短暂状态并等待最新版本，不展示旧文档；失败可返回编辑。

复用另一 WebView 的代价是焦点、DPI、屏幕阅读、双页工具栏和消息路由增加。若选择把 HTML 阅读容器置于当前 WebView，则需新增结果桥接、隔离 DOM 与 CSS，改造范围更大。默认不选择后者；实施前用小原型比较两条路径，不把历史 viewMode 兼容字段当成自动恢复入口。

## 7. 无障碍与 Windows 适配

- 普通文字对比度目标 ≥4.5:1，大字 ≥3:1；必要图形/边框和焦点目标 ≥3:1。玻璃背景、五种配色、禁用项、错误和链接逐项实测；浅色 muted 不能凭肉眼判合格。[WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- 保留 36×36 px 桌面操作目标；新增复制/关闭不小于 32×32 px，触屏关键入口争取 44×44 px。WCAG AA 的最小目标原则是 24 CSS px 及其例外，44 px 是更高的可操作目标，不误写成 AA 强制要求。[Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- 图标按钮具有中文可访问名称，开关报告状态；复制反馈用轻量 `aria-live`，不抢焦点。悬停操作也必须在 `focus-within` 和触屏入口可达。
- 正文文字放大 200%，320 CSS px 等效重排宽度检查功能完整；二维表格/公式/代码允许局部横滚，但不得把整页变成双向滚动。[Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
- 覆盖行高 1.5、段后 2em、字距 0.12em、词距 0.16em 的组合，检查没有内容丢失。它们是覆盖后的容错要求，不是默认排版必须照抄的参数；结合中文适用性判断。[Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)
- 目录、灯箱和菜单关闭恢复触发点；无焦点陷阱，Esc 行为不破坏输入法；固定层不遮住获得焦点的元素。[Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)
- 强制配色使用 Windows 系统色，去玻璃、阴影和依赖颜色的语义；减少动画尊重系统、应用与媒体偏好。
- 在真实 EXE 验证 100/125/150/200% DPI、窗口拖至不同 DPI 显示器、设置关闭后焦点、中文输入法候选框与正文光标。Narrator 的语义阅读需单列验收，浏览器快照不代表完成。

### 8.2 安全与内容保真

继续保留 HTML 禁用、DOMPurify、来源/session/protocol/version 校验、字段白名单、大小上限与导航限制。生成公式/图表增加的白名单仅作用于相应输出，不扩展普通 Markdown 能力。剪贴板文本从源内容提取；任何新原生命令限定功能、校验请求，不提供通用磁盘 API。[WebView2 安全建议](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/security)

新增渲染模块处理顺序：当前版本的 AST/HTML → 基础净化与受控元数据 → 按明确节点类型渲染 → 输出类型专用净化/校验 → 可见 DOM。结果携带版本，关闭/换文档/主题变化后失效的任务不能重新插入页面。

禁止 `UseAdvancedExtensions()` 一次启用所有扩展；批准的语法逐项加入，记录编辑 AST 与 Markdig 不一致的样例及降级规则。现有 pipeline 的额外强调仅启用删除线；上线新支持前核实锁定 Markdig 版本的 API，而非假定在线最新文档与 1.4.0 完全一致。[Markdig Usage](https://xoofx.github.io/markdig/docs/usage/)

### 8.3 性能与降级

首轮复用已有更新与统计节流；不每次按键重新生成全篇组件。新增缓存只在实测需要时按“类型/源内容/渲染版本/主题”缓存，设置有界总量，换文档清理引用。

建议验收预算：同机同文档普通输入延迟 p95 相比基线增幅 ≤10%；10 万字符文档首屏可交互时间增幅 ≤20%；复杂组件超出预算时保留源码并提示局部降级。以上为待标定目标，记录硬件、Runtime、原始耗时与样本数；没有基线就不能宣称通过。

保留现有桥接/文件限制：文件 8 MiB、桥接文本 1 Mi UTF-16 单元、预览 HTML 4 Mi 字符等限制并不相同，性能样例须在适用边界内。JS/TS 高亮已有 100000 字符上限，不能升级依赖后移除降级。

公式初始建议单条 ≤8 Ki 字符、限制宏展开；图表初始建议 ≤32 Ki 字符并限制边/节点规模，具体值由压测确定。不能依靠 `Promise.race` 真正中断同线程同步渲染；若需要硬超时，必须验证 Worker/隔离路径是否适用，否则用复杂度限制和主动源码降级。
