# Marker 工程开发指南

本文记录当前仓库可以执行的开发与构建流程。程序仍处于 M0：WinUI 3 窗口只显示 `Marker M0`，Web 资源依赖尚未连到窗口，尚未实现 Markdown 编辑、预览或文件读写。

## 固定决策与目标环境

- 产品和包身份：`Marker`；开发证书主题：`CN=Marker.Dev`。
- 许可证：MIT，项目维护者负责许可证决策与发布合规。
- 最低系统：Windows 11 24H2 / build 26100；首发架构 x64。
- 分发已选定站外 MSIX；Microsoft Store 保留为候选。正式签名流程采用维护者提供的受信任代码签名证书或签名服务，对已验证的未签名产物签名、验证并安装验收；供应方和凭据尚待落实，是 M5 前置条件。
- 桌面端：.NET 10，WinUI 3，Windows App SDK `2.5.1`；Windows SDK Build Tools NuGet 包 `10.0.26100.9169`。
- Web 工程：Node `24.19.x`、npm `12.x`、Vite `8.3.3`、TypeScript `7.0.2`；CodeMirror 6 直接依赖版本见 `src/Marker.Web/package.json`。
- WebView2 Evergreen Runtime 面向用户机器；本地开发机有无 Visual Studio IDE 不影响 CLI 构建，MSIX 打包仍要求匹配的 Windows SDK 工具链。

`global.json` 将 .NET SDK 固定为 `10.0.401` 且禁止 roll-forward。开发者已有完全匹配的全局 SDK 时直接使用；否则 `scripts/bootstrap.ps1` 会从微软 SDK 发布地址下载 zip、核验固定 SHA-512 并解压到仓库 `.tools/dotnet`。该脚本不会运行系统安装器或修改机器级 SDK。下载需要网络。

## 日常构建

在仓库根目录用 PowerShell 执行：

```powershell
./scripts/bootstrap.ps1
./scripts/build.ps1
```

`bootstrap.ps1` 在 `.tools/dotnet/dotnet.exe` 已存在时只检查其版本；缺失时才下载并校验 SDK。它不修改全局 PATH，也不安装 Visual Studio。

`build.ps1` 依次执行：

1. Web 工程 `npm ci`、`npm run check` 和 `npm run build`。
2. 对 `Marker.sln` 进行锁文件模式 NuGet restore。
3. 构建 x64 Release。
4. 执行 MSTest 工程。

脚本把 NuGet、npm 缓存和 dotnet CLI 状态放在 `.tools`。依赖锁文件分别是 `src/Marker.Web/package-lock.json`、`src/Marker.App/packages.lock.json` 和 `tests/Marker.Tests/packages.lock.json`。日常构建必须保持锁定依赖。

### 更新依赖锁

只有在有意升级或新增依赖时才执行：

```powershell
./scripts/build.ps1 -UpdateLockfile
```

该开关允许 NuGet restore 重写锁文件；npm 仍通过 `npm ci` 使用现有 package-lock。检查并提交实际依赖变更和锁文件，不要把它作为日常构建命令。

### 生成 MSIX

```powershell
./scripts/build.ps1 -Package
```

包放在 `artifacts/msix/`，目标为 x64、自包含的未签名 MSIX。自包含表示打包 Windows App SDK 和 .NET 应用运行时依赖；WebView2 Evergreen Runtime 仍由目标机器提供。`artifacts/` 已加入 `.gitignore`。

## 开发签名与安装

### 仅签名

```powershell
./scripts/install-dev.ps1 -PackagePath <MSIX完整路径>
```

脚本只接受包身份为 `Marker` / `CN=Marker.Dev` 的包。没有有效证书时，它会在当前用户的 `CurrentUser\My` 创建一年期、不可导出的开发签名证书；将公钥导出到 `artifacts/Marker.Dev.cer`，并导入当前用户的 `CurrentUser\TrustedPeople`，随后签名 MSIX。此操作会改变当前用户证书存储。私钥不会作为 PFX 导出或提交。

默认命令只签名，不安装。自签名 MSIX 的本机安装需将测试证书公钥加入 `LocalMachine\TrustedPeople`，仅当前用户信任不足；本次已实测该区别。管理员操作只使用 TrustedPeople，不向 Root 库导入开发签名证书。见微软[包签名证书指南](https://learn.microsoft.com/en-us/windows/msix/package/create-certificate-package-signing)。

### 机器信任并安装

```powershell
./scripts/install-dev.ps1 -PackagePath <MSIX完整路径> -TrustMachine
```

`-TrustMachine` 会把证书导入 `LocalMachine\TrustedPeople`、验证签名并安装包，需要管理员权限，并留下机器级信任记录。使用后应核对确切证书指纹并按维护者决定清理。不要把开发证书用于公开发布。

### 临时安装烟雾测试

M1 使用 `./scripts/test-msix.ps1 -PackagePath <MSIX完整路径> -M1`。除安装启动外，脚本通过 UI Automation 等待 `预览已同步 · v0`，在真实 WebView 中发送测试按键后检查预览新版本，再正常关闭窗口。截图保存为 `artifacts/marker-m1.png`，结果仍为 `artifacts/msix-smoke.json`。它不覆盖中文输入法组合和候选框定位。下文空窗口结果为 M0 历史记录。

```powershell
./scripts/test-msix.ps1 -PackagePath <MSIX完整路径>
```

该脚本要求管理员 PowerShell，且拒绝覆盖已有 Marker 开发版安装。它签名并安装包、启动窗口、截图到 `artifacts/marker-m0.png`，然后关闭进程、卸载临时包，并移除本次新加的机器信任。若该证书原本已在机器信任存储中，脚本会保留它。此烟雾测试已在 Windows build 26300 实测通过：安装包 `Marker_0.1.0.0_x64__aew9p86h2zp2w`，窗口标题 `Marker`，正文 `Marker M0`；进程已关闭，应用已卸载，`machineTrustRemoved=true`。测试不会删除当前用户证书及其私钥；当前用户 `My` 私钥和 `TrustedPeople` 信任仍保留。

## M1 原型检查与人工验收

编辑页和预览页由 Vite 多入口构建，资源随 MSIX 本地分发。WinUI 使用 WinRT 的 `CreateWithOptionsAsync` 创建共享环境，用户数据目录显式指向 LocalApplicationData 下的 Marker/WebView2；API 投影依据见微软 [WinRT WebView2 环境参考](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/winrt/microsoft_web_webview2_core/corewebview2environment?view=webview2-winrt-1.0.3719.77)。

Web 行为使用现有 Playwright MCP 验证：在 `src/Marker.Web` 运行 `npm exec vite preview -- --host 127.0.0.1 --port 5173 --strictPort`，然后让 MCP `browser_run_code_unsafe` 执行 `scripts/test-web-m1.js` 的完整路径。该脚本在独立浏览器上下文中模拟 host 消息，检查快照、Ctrl+Z/Ctrl+Y、重同步和恶意 HTML，不给产品代码增加测试接口。完成后脚本关闭上下文，并需关闭本次 Vite 进程和 MCP 页面。

真实 IME 验收已收到用户反馈，大部分通过，但微信输入法候选框异常待修复和复测。验收时记录 Windows build、WebView2 Runtime、输入法名称/版本和缩放；连续输入中文/中英混合及 emoji，观察未提交组合文本与候选框位置；提交后检查预览，再执行 Ctrl+Z/Ctrl+Y、跨编辑/预览/原生按钮切换焦点和浮层操作。重同步后检查文本、光标和撤销历史。不得用模拟按键或浏览器 `insertText` 结果填报 IME 通过。

M1 仅为内置样例原型，不提供打开或保存。未完成真实 IME 和安全集成退出检查前，M2 文件闭环保持待实施。当前预览有意移除图片、链接和任务 checkbox 控件；完整语法表现及本地图片策略由后续阶段实现。

## 编辑器新段落快捷键

`Ctrl+Enter` 在当前逻辑行后插入两个换行，并将光标移到新段落。一次 `Ctrl+Z` 可撤销这次换段，`Ctrl+Y` 可恢复；已有文本不会被替换。编辑器标题显示此快捷键。`Enter` 仍按 Markdown 源码编辑规则插入单换行，段落间的空行由 `Ctrl+Enter` 一次完成。文档末尾空白点击当前仍是定位光标，不会隐式修改文本。

微信输入法、多显示器、200% 缩放环境已收到候选框不可见或落屏外反馈，且刚启动也出现；该问题仍在诊断，不能将 Ctrl+Enter 修复或自动按键测试视为候选框修复。

宿主对照结果：微信输入法在 Marker 编辑器及临时普通 textarea 中异常，在独立 Edge 与临时原生窗口 WebView2 中正常；微软拼音在 Marker 正常。可临时用微软拼音完成编辑体验检查，但不能据此将微信输入法兼容项标为通过。对照环境、缩放采样限制与后续宿主实验见[项目历程](progress.md)。

应用内原生子窗口宿主实验未通过真实鼠标/键盘编辑检查，已恢复双 XAML WebView2。后续宿主验收必须同时确认原生点击命中、键盘焦点、实际文本修改及预览更新；CDP 输入成功不能替代真实桌面输入验证。实验源码仅保存在本机 `.tools/native-host-experiment/`。
