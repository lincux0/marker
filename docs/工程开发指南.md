# Marker 工程开发指南

本文记录当前仓库可以执行的开发与构建流程。当前生产代码采用 M2 本地文档闭环、M3 增量编辑协议和 M4 Windows 集成，并使用 CodeMirror 6 单页即时呈现编辑。Win32 主窗口通过原生子 HWND 的 WebView2 显示编辑器及 HTML/CSS 浮动工具栏；另一个隐藏 WebView2 继续处理 Markdig 解析和受控图片资源。WinUI XAML Island 缩为 1×1，仅保留旧字段和 handler 的兼容路径。当前 EXE 构建及用户验收结果见项目历程；独立 Islands 原型保留作早期验收参考，不进入解决方案和 MSIX。

## 固定决策与目标环境

- 产品和包身份：`Marker`；开发证书主题：`CN=Marker.Dev`。
- 许可证：MIT，项目维护者负责许可证决策与发布合规。
- 最低系统：Windows 11 24H2 / build 26100；首发架构 x64。
- 分发已选定站外 MSIX；Microsoft Store 保留为候选。正式签名流程采用维护者提供的受信任代码签名证书或签名服务，对已验证的未签名产物签名、验证并安装验收；供应方和凭据尚待落实，是 M5 前置条件。
- 桌面端：.NET 10，WinUI 3，Windows App SDK `2.5.1`；Windows SDK Build Tools NuGet 包 `10.0.26100.9169`。
- Web 工程：Node `24.19.x`、npm `12.x`、Vite `8.3.3`、TypeScript `7.0.2`；CodeMirror 6 直接依赖版本见 `src/Marker.Web/package.json`。
- WebView2 Evergreen Runtime 由目标机器提供；启动前 Marker 会检查运行时并提示安装，不会自动下载安装器。本地开发机有无 Visual Studio IDE 不影响 CLI 构建，MSIX 打包仍要求匹配的 Windows SDK 工具链。运行时下载入口见[微软 WebView2](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)。

`global.json` 将 .NET SDK 固定为 `10.0.401` 且禁止 roll-forward。开发者已有完全匹配的全局 SDK 时直接使用；否则 `scripts/bootstrap.ps1` 会从微软 SDK 发布地址下载 zip、核验固定 SHA-512 并解压到仓库 `.tools/dotnet`。该脚本不会运行系统安装器或修改机器级 SDK。下载需要网络。

## 日常构建

### 当前用户 Setup.exe

在仓库根目录执行 `./scripts/build-setup.ps1`，先完成现有 Release 构建/测试，再生成 `artifacts/setup/Marker-Setup-<版本>-x64.exe` 和 `.sha256` 校验文件。已经完成同一源码的 Release 验证时可加 `-SkipBuild`。编译器缓存于 `.tools/innosetup-6.7.3`，首次下载校验固定 SHA-256 与官方签名；版本取自应用 manifest。

双击安装包即可仅为当前用户安装，默认目录 `%LOCALAPPDATA%/Programs/Marker`，从开始菜单启动。需要 Windows 11 24H2 起的 x64 和 Microsoft Edge WebView2 Runtime；运行时缺失时安装器提示，不自动下载。安装包目前未签名，Windows 可能显示安全提示。卸载保留 `%LOCALAPPDATA%/Marker/settings.db`、恢复草稿与用户 Markdown 文件。测试包安装到独立目录后已完成启动、正常退出与卸载；升级覆盖和最低系统仍待验。

### Release 与 MSIX

在仓库根目录用 PowerShell 执行：

```powershell
./scripts/bootstrap.ps1
./scripts/build.ps1
```

`bootstrap.ps1` 在 `.tools/dotnet/dotnet.exe` 已存在时只检查其版本；缺失时才下载并校验 SDK。它不修改全局 PATH，也不安装 Visual Studio。

`build.ps1` 依次执行：

1. Web 工程 `npm ci`、`npm run check` 和 `npm run build`。
2. 对 `Marker.sln` 进行锁文件模式 NuGet restore。
3. 构建 x64 Release。
4. 执行 MSTest 工程。

脚本把 NuGet、npm 缓存和 dotnet CLI 状态放在 `.tools`。依赖锁文件分别是 `src/Marker.Web/package-lock.json`、`src/Marker.App/packages.lock.json` 和 `tests/Marker.Tests/packages.lock.json`。日常构建必须保持锁定依赖。

### 更新依赖锁

只有在有意升级或新增依赖时才执行：

```powershell
./scripts/build.ps1 -UpdateLockfile
```

该开关允许 NuGet restore 重写锁文件；npm 仍通过 `npm ci` 使用现有 package-lock。检查并提交实际依赖变更和锁文件，不要把它作为日常构建命令。

### 生成 MSIX

```powershell
./scripts/build.ps1 -Package
```

包放在 `artifacts/msix/`，目标为 x64、自包含的未签名 MSIX。自包含表示打包 Windows App SDK 和 .NET 应用运行时依赖；WebView2 Evergreen Runtime 仍由目标机器提供。`artifacts/` 已加入 `.gitignore`。

## M4 外观、动效与设置

可见工具栏固定在编辑 WebView 视口中，屏幕两侧边距为 32–56 CSS px，并以 `backdrop-filter` 模糊其下方滚动正文。原生子窗口 WebView2 从客户区 `(0,0)` 开始铺满窗口；工具栏和 CodeMirror 正文处于同一页面，不发生跨 HWND 叠放。工具栏展示常用文档命令、恢复草稿、撤销/重做、查找替换和设置。设置仍由独立窗口提供。代码模式按钮常态只显示图标，但保留 Tooltip、无障碍名称及命令溢出项文字。快捷键包括 `Ctrl+N` 新建、`Ctrl+O` 打开、`Ctrl+S` 保存、`Ctrl+Shift+S` 另存为、`Ctrl+F` 查找、`Ctrl+H` 替换、`Ctrl+Z` 撤销、`Ctrl+Y` 重做、`Ctrl+Alt+M` 切换源码标记显示。

Win32 根窗体保留 DWM 主窗口 backdrop；原先可见原生 Island 工具栏的 Acrylic、渐变描边和 `ThemeShadow` 方案已由 D018 替代。当前玻璃效果由 WebView2 中浮动工具栏的 CSS `backdrop-filter` 提供，它可显示同一 WebView 页面内滚动经过其后的正文。高对比模式在 CSS 中停用模糊和透明材质并使用 Windows 系统色。系统主题、颜色、高对比与 Windows 动画设置变化会实时应用。

颜色组合同时应用于 Web 正文、隐藏预览及 HTML/CSS 工具栏，并同步宿主客户区、标题栏 caption 和设置窗口背景/强调色。原生 `WritingPalette.GetColors` 与 Web CSS 使用相同背景/强调色；高对比下 Windows 系统颜色优先。

“减少动画”设置与 Windows `UISettings.AnimationsEnabled` 一起控制 Marker 自定义 Composition 和 Web 内容 CSS 动画；开启减少动画后即时停止正在播放的 Marker Composition 动画。该选项不关闭 WinUI 控件内置动画，WinUI 内置行为仍由 Windows 的辅助功能策略控制。可见工具栏和正文现位于同一 WebView2 页面；隐藏 XAML Island 不承载可见入场动画。

窗口首次以 960×700 DIP 打开，正常拖拽最小尺寸为 720×480 DIP；均按目标屏 DPI 换算。退出时保存普通窗口位置与最大化状态；恢复时将移除显示器上的位置夹进当前有效工作区，并按 `WINDOWPLACEMENT` workspace 坐标换算规则处理任务栏偏移。系统标题栏、最大化按钮和 Windows Snap 布局保持原生行为。位置保存在 `%LocalAppData%\Marker\settings.db`；损坏或未知版本数据库仍不会被覆盖。

## M2 本地文档工作流

工具栏提供“新建、打开、保存、另存为、恢复草稿”。编辑器快捷键为 `Ctrl+N` 新建、`Ctrl+O` 打开、`Ctrl+S` 保存、`Ctrl+Shift+S` 另存为、`Ctrl+Enter` 在当前行后新建段落；关闭窗口也会走未保存确认。

打开文件会先解码后再询问如何处理当前文档。程序严格读取 UTF-8（有/无 BOM）和带 BOM 的 UTF-16 LE/BE；无法解码时可以明确选择 GB18030。编辑期间文本统一为 LF，保存会恢复编码、BOM 和换行元数据。遇到混合换行时，“是”选择 CRLF、“否”选择 LF、“取消”不保存。

保存前原生侧会通过 `requestId` 向编辑器取最新完整快照；输入法组合尚未提交时会停止保存，用户需先完成选词。文件最多 8 MiB，桥接 JSON 最多 2 MiB，文本最多 1 Mi UTF-16 单元。目标文件外部修改或删除时会展示冲突选项：重新载入、另存为副本或取消并保留当前编辑。SHA-256 指纹是保存时的最终保护；同目录临时文件写入并 flush 后才原子替换。替换竞态检测到的外部版本保留为 `.external` 文件并显示实际路径。

恢复草稿位于 `%LocalAppData%\Marker\Recovery`，采用每文档一个 schemaVersion 1 JSON 文件，大小最多 8 MiB。启动时发现草稿会提示恢复；恢复结果是未命名副本，原路径只用于显示来源与差异，不会自动写回原文件。关闭未保存文档时可选择保存、放弃或取消；草稿写入失败时会显示提醒。

另存为到其他目录时，当前实现会提示相对图片引用可能失效；本阶段不会复制或改写图片资源。预览只处理当前 Markdown 所在目录中的相对 PNG/JPEG/GIF/WebP/BMP 图片，单张最多 16 MiB；绝对路径、越界路径、重解析点和超过大小限制的图片会被移除，不向 Web 内容暴露原始磁盘路径。目录树、多标签、图片插入和复制资产尚未实现。

### 本机文件闭环脚本

`scripts/test-file-workflow.ps1` 使用本机 Release EXE、真实 Win32 文件选择器与真实临时文件夹检查打开/保存/冲突/另存为/清理。默认运行脚本会关闭本次启动的 Marker 进程并清理临时夹具：

```powershell
./scripts/test-file-workflow.ps1
```

使用 `-BrowserInput` 时，脚本会在实际打开原生 Open/Save As picker 后暂停，等 Playwright MCP/CDP 对 CodeMirror 输入当前请求的测试文本。该测试输入由浏览器自动化执行，**不模拟或验收 Windows IME**。按以下顺序完成两个输入阶段：

1. 单独 PowerShell 窗口运行 `./scripts/test-file-workflow.ps1 -BrowserInput` 并保持窗口运行。脚本启动本次 Release EXE、自动打开测试 Markdown 后，会写出 `artifacts/m2-browser-input.json`，字段包含 `stage`、`marker`、`done`、`pid` 与夹具目录。
2. 用项目已连接的 Playwright MCP `browser_run_code_unsafe` 执行下面的浏览器代码，连接 `http://127.0.0.1:9222`。把 JSON 当前的 `marker` 字段粘入代码：

   ```javascript
   async (page) => {
     const browser = await page.context().browser().browserType().connectOverCDP("http://127.0.0.1:9222");
     const editor = browser.contexts().flatMap((context) => context.pages())
       .find((candidate) => candidate.url().startsWith("https://editor.marker.example/"));
     if (!editor) throw new Error("Marker editor WebView was not found.");
     await editor.locator(".cm-content").click();
     await editor.keyboard.press("Control+End");
     await editor.keyboard.press("Enter");
     await editor.keyboard.insertText("粘贴当前请求中的 marker");
     await editor.keyboard.press("Control+s");
   }
   ```

   确认 MCP 操作已完成，再在 PowerShell 中创建 JSON 的 `done` 路径：

   ```powershell
   $request = Get-Content artifacts/m2-browser-input.json -Raw | ConvertFrom-Json
   New-Item -ItemType File -LiteralPath $request.done | Out-Null
   ```

3. 脚本接着会验证保存、制造并取消一次外部文件冲突，再将请求 JSON 更新为 `stage=afterCancel` 和新的 marker。对新 marker 重复第 2 步并创建新的 `done` 文件。随后脚本会验证继续编辑、原生 Save As picker 及同目录副本。
4. 结果见 `artifacts/file-workflow-smoke.json`。`-BrowserInput` 模式为方便 MCP 操作会刻意保留本次 Marker 进程和夹具；结果 JSON 的 `processId` 与请求 JSON 的 `pid` 指向本次应用。检查结果后正常关闭该窗口并确认进程退出，再关闭 MCP 页面。只删除结果 JSON 中 `fixtureRoot` 指向的本次 `artifacts/m2-workflow-*` 目录，不做通配删除。

这组闭环已在本机通过；它不覆盖 MSIX 安装、最低 build、读屏器、磁盘耗尽、断电或完整崩溃时序。恢复约每秒落盘、编辑器约每 100 ms 同步的设计仍可能在突然终止时丢失最新未写入尾部内容。最新状态见[项目历程](progress.md)。

## 历史 M4 网页、文件激活与截图检查

以下双视图/分栏操作属于 D016 之前的验收流程；当前预览窗口不可见，旧脚本的可见窗口与焦点断言不适用。单页网页短检查使用 `scripts/test-live-edit.js`，在下述 Vite preview 服务上通过现有 Playwright MCP 的 `browser_run_code_unsafe` 传入脚本绝对路径。该脚本检查隐藏标记、原文快照、表格布局、鼠标/键盘任务勾选、直接编辑、撤销重做、源码快捷键、闭合标记退格、受控图片 URL 和减少动画；不替代桌面 IME 验收。

`scripts/test-web-m4.js` 使用现有 Playwright MCP 检查 editor/preview 的高对比与减少动画样式、空文档提示、查找替换焦点和 WebView2 AdditionalObjects 文件消息。它以浏览器 `File` 对象模拟宿主消息，**不代替真实 WebView2 文件对象或 Windows 拖放验收**。先在独立 PowerShell 窗口准备本地 Web 资源：

```powershell
Push-Location src/Marker.Web
npm ci
npm run check
npm run build
npm exec vite preview -- --host 127.0.0.1 --port 5173 --strictPort
```

再通过项目已连接的 Playwright MCP 调用 `browser_run_code_unsafe`，把 `scripts/test-web-m4.js` 的绝对路径作为 `filename`。脚本完成后关闭本次 MCP 页面/上下文和 Vite 窗口；结果只证明 mock Web 页面检查通过。

`scripts/test-webview-m4.js` 在真实 Marker WebView2 的临时 CDP 端口上检查编辑/预览两页的磁盘 File 对象，以及伪造 File、带路径 JSON 和缺少 AdditionalObjects 消息的拒绝。它需要分栏模式、未保存编辑已处理，并先在仓库中准备两个测试夹具：

```powershell
[IO.File]::WriteAllText((Join-Path (Get-Location) 'artifacts/m4-drop-fixture-editor.md'), "# M4_NATIVE_DROP_EDITOR`n", [Text.UTF8Encoding]::new($false))
[IO.File]::WriteAllText((Join-Path (Get-Location) 'artifacts/m4-drop-fixture-preview.md'), "# M4_NATIVE_DROP_PREVIEW`n", [Text.UTF8Encoding]::new($false))
```

按本指南真实宿主检查的方式，只对本次测试进程启用 `--remote-debugging-port=9222`，再通过相同 MCP 的 `filename` 执行该脚本。脚本中的夹具路径默认是 `D:\marker\artifacts`，其他克隆路径需对应修改。该检查使用 CDP 注入磁盘对象，不代替 Explorer OLE 拖动或已安装 MSIX 文件关联。文件拖放在 document 捕获阶段拦截，防止 CodeMirror 自行读取文件并插入当前文档；普通选区文本拖放仍由编辑器处理。

`scripts/test-activation-m4.ps1` 是 Release EXE 的原生 smoke，需以 STA PowerShell 启动；它检查命令行文件启动、第二进程转发、忽略 `.txt`、原生 OLE 文件拖放及脏文档取消后保留当前编辑。运行前关闭所有 Marker 进程：

```powershell
powershell.exe -STA -File ./scripts/test-activation-m4.ps1
powershell.exe -STA -File ./scripts/test-activation-m4.ps1 -DropTarget editor
powershell.exe -STA -File ./scripts/test-activation-m4.ps1 -DropTarget preview
```

脚本拒绝接管已运行的 Marker，生成独立的 `artifacts/m4-activation-*` 夹具与 `result.json`，退出时关闭自己启动的进程并恢复已有 `%LocalAppData%\Marker\settings.db` 字节（运行前拒绝未处理的 SQLite 日志）；不会自动删除结果夹具。该脚本启动 EXE 并传命令行参数，不等于已验证安装 MSIX 后资源管理器文件关联。拖放由模拟文件拖动器触发，只覆盖该脚本所执行的输入路径，不验证中文输入法。脚本需要 Release EXE 已按当前源码构建。

查看外观时可运行 Release EXE 并用截图脚本抓取指定 PID 的窗口。脚本仅接受本仓库 Release EXE 路径与 `artifacts/` 下的 PNG，不启动或关闭应用：

```powershell
$exe = (Resolve-Path 'src/Marker.App/bin/x64/Release/net10.0-windows10.0.26100.0/win-x64/Marker.App.exe').Path
$marker = Get-CimInstance Win32_Process | Where-Object ExecutablePath -eq $exe | Select-Object -First 1
if (-not $marker) { throw '请先启动 Marker Release EXE。' }
./scripts/capture-marker.ps1 -ProcessId $marker.ProcessId -OutputPath (Join-Path (Get-Location) 'artifacts/m4-shell.png')
```

截图应确认 200% 缩放下主窗口与设置窗口完整、Web 浮动工具栏固定在正文上方，水平边距随窗口宽度保持 32–56 CSS px；滚动正文能从半透明工具栏后方可见，且没有另一个 HWND 遮挡或露出窗口异色边框。检查高对比回退及颜色在工具栏、标题栏、设置窗口和纸面间一致。截图不替代屏幕拓扑或 IME 实机验收。系统材质依据见 [Fluent 2 motion](https://fluent2.microsoft.design/motion)、[Mica](https://learn.microsoft.com/en-us/windows/apps/design/style/mica)；窗口位置换算参考 [WINDOWPLACEMENT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-windowplacement)，WebView2 文件对象映射见 [AdditionalObjects](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/winrt/microsoft_web_webview2_core/corewebview2webmessagereceivedeventargs#additionalobjects)。

`.github/workflows/build.yml` 在 `windows-2025` runner 上安装指定的 .NET 与 Node 版本，运行上述检查并上传未签名 MSIX。工作流存在不代表远端已成功运行；报告 CI 状态前应检查对应 Actions 运行记录。当前远端 CI 尚未执行，也没有 Git push。

## 单页编辑、查找与设置

可见顶栏与编辑器同处 WebView2 页面，固定于视口并通过 CSS 背景模糊正文；编辑区仍是同一个 CodeMirror 实例和相同的 windowed WebView2 输入宿主。顶部“代码模式”与 `Ctrl+Alt+M` 使用同一编辑器切换原始 Markdown/即时呈现，不重置光标和撤销历史。文档操作、撤销/重做、查找/替换集中在顶栏；顶栏已按人工验收反馈取消应用图标，文档名保留且不再单独占行，超长名称悬停可查看完整内容。忽略不支持的启动参数时不显示常态通知，真实文件错误仍提示。

撤销、重做、查找、替换与代码模式按钮调用编辑器本地命令；新建、打开、保存、另存为、恢复草稿和设置通过既有原生 `command` 桥接处理。`recover`、`settings` 是新增白名单值，其他命令 envelope 仍校验页面来源、协议版本、当前会话和精确字段。原生宿主以 `toolbarState` 消息同步文档标题、用户通知和 busy 状态；该消息绑定当前编辑器来源及会话。

常用格式快捷键参考 [Typora 官方 Windows 快捷键](https://support.typora.io/Shortcut-Keys/)，当前支持：

| 操作 | 快捷键 |
|---|---|
| 加粗 / 斜体 | `Ctrl+B` / `Ctrl+I` |
| 行内代码 | `Ctrl+Shift+反引号` |
| 删除线 | `Alt+Shift+5` |
| 插入链接 | `Ctrl+K` |
| 一级至六级 ATX 标题 | `Ctrl+1` 至 `Ctrl+6` |
| 恢复普通段落（移除 ATX 前缀） | `Ctrl+0` |
| 代码模式 | `Ctrl+Alt+M` 或顶栏按钮 |

行内格式作用于选中文字，再次按同一快捷键可移除相同的外层标记；没有选区时插入并选中“文本”占位，直接输入即可替换。链接使用 `(url)` 地址占位，请切换代码模式填写实际 URL。标题快捷键处理所选行，相同标题级别再次按下可取消。格式命令可独立撤销，组合输入期间拒绝执行；常用单行与 ATX 转换之外的复杂嵌套格式仍可在代码模式手动编辑。

`scripts/test-formatting.js` 与 `scripts/test-writing-layout.js` 使用同一 Playwright MCP/本地 Vite preview 条件，分别检查快捷键/模式同步和标题/换行表格/任务框排版；输入保护采用合成事件，不能替代微信输入法整机验收。

设置窗口分为外观、排版和字体卡片，设置即时应用并保存。外观保留系统/浅色/深色主题与减少动画，另提供薰衣草、森林、海洋、纸张、石墨五组颜色组合。颜色组合通过共用配色源同步应用到 Web 正文/隐藏预览与指定的原生窗口背景及强调区域；Windows 高对比色优先。设置窗口由主窗口拥有，单例显示；主窗口关闭时一并关闭，窗口位置按 owner DPI 换算并限制在当前显示器工作区。

排版保留自动换行、字号 12–24 和行高 1.2–2 倍；新增段间距 0–2 em，默认 0.5 em。段间距通过顶层段落末尾的内边距呈现，不改变或删除 Markdown 空行。正文字体、H1 和 H2 可分别选择系统、宋体、微软雅黑、等线或衬线字体；默认正文系统字体，H1/H2 宋体。字体仅引用 Windows 本机字体，并设置回退链。

字号、行高与段间距使用直接数值输入，保留已定义范围和系统键盘焦点指示。正文行不显示悬停/点击底色；标题留白使用内边距，避免编辑器行高测量漏算外边距。

CodeMirror 6 的单页正文默认以解析样式呈现常见 Markdown 标记，完整 Markdown 原文仍是唯一编辑文档并沿用既有增量同步、撤销历史和保存协议。按 `Ctrl+Alt+M` 可在同一编辑器显示/隐藏源码标记，方便修改复杂语法与链接地址。即时呈现复用 CodeMirror GFM 语法树；Markdig 同一 AST 另提供带 session/version 的 `richContent` range，用于数学、脚注和五类已知提示框，避免在全文扫描美元符号。数学 widget 受光标/选择上下文约束显示原文；脚注在原位置显示定义，支持最近引用回跳；提示框只转换已知 marker 并保留正文。Mermaid 在可见编辑器中按需加载，支持受限图类型与安全输出。编辑后旧 metadata 立即失效，源文档始终可编辑。复杂表格结构编辑、参考式图片及 HTML 仍有边界，CodeMirror 呈现不承诺与 Markdig HTML 完全一致。详细专业语法规则见[技术决策 D026](decision.md)。

## 开发签名与安装

### 仅签名

```powershell

```

脚本只接受包身份为 `Marker` / `CN=Marker.Dev` 的包。没有有效证书时，它会在当前用户的 `CurrentUser\My` 创建一年期、不可导出的开发签名证书；将公钥导出到 `artifacts/Marker.Dev.cer`，并导入当前用户的 `CurrentUser\TrustedPeople`，随后签名 MSIX。此操作会改变当前用户证书存储。私钥不会作为 PFX 导出或提交。

### 本地设置数据库

设置及窗口位置保存在 `%LOCALAPPDATA%\Marker\settings.db`，设置控件修改后立即事务保存，退出/重启时重新加载。数据库首次建立时导入旧 `settings.json`，原文件保留；此后仅以数据库为准。旧 JSON 损坏不再永久阻止新设置保存。

备份设置前关闭 Marker，再复制 `settings.db`；不要在程序运行时单独复制正在写入的数据库。损坏/未来数据库会保留并禁写，先备份再处理，勿直接删除用户数据。恢复草稿与 Markdown 文件仍按原有流程存储。

若提示版本 0，先在实际启动应用的用户 PowerShell 中核对文件长度。零字节文件没有可读取的 SQLite 设置，不能直接改版本号；自动化工具可能处于不同文件视图，不能用工具侧正常数据库证明桌面应用正常。仅当实际文件为零字节、没有 `-journal`/`-wal`/`-shm` 时，可在该用户 PowerShell 中执行以下命令，将空文件改名保留。它通过文件共享模式阻止并发写入，非空或占用中的数据库会停止处理：

```powershell
$p = Join-Path $env:LOCALAPPDATA 'Marker\settings.db'
foreach ($suffix in '-journal','-wal','-shm') {
    if (Test-Path -LiteralPath ($p + $suffix)) { throw '存在数据库日志，停止恢复。' }
}
$backup = $p + '.empty-' + [Guid]::NewGuid().ToString('N') + '.bak'
$stream = [IO.File]::Open($p, [IO.FileMode]::Open, [IO.FileAccess]::Read, [IO.FileShare]::Delete)
try {
    if ($stream.Length -ne 0) { throw '数据库非空，停止恢复。' }
    [IO.File]::Move($p, $backup)
    "原空库已保留：$backup"
} finally { $stream.Dispose() }
```

随后关闭并重新打开设置，触发现有加载重试和首次数据库迁移；有效旧 `settings.json` 会被导入，否则使用默认设置。旧 JSON 和空库备份均保留。若显示“旧设置文件无法读取或版本不兼容，已保留原文件并改用默认设置”，这是首次迁移通知，新数据库仍可保存；成功保存设置或正常重启后清除。调整一项设置后，退出并从原快捷方式重启，核验持久化。该步骤不会恢复空库已经缺失的设置，也不适用于非空损坏库或未来版本。

`SettingsDatabaseTests` 覆盖跨连接恢复、所有字段、JSON 迁移和失败事务回滚；真实退出重启是否恢复以及最终构建证据见项目历程。

Web 依赖许可文本由 `node scripts/update-web-licenses.mjs` 从锁文件生产闭包和实际包内 LICENSE/NOTICE 生成，已纳入 `scripts/build.ps1` 的 npm ci 后步骤；新增或升级依赖时核对 `installer/licenses/WebThirdParty.txt` 的 diff 和生成报告。

打开文档被外部程序修改时，底部显示“磁盘中文件已被修改，是否重新加载？”。“关闭”仅收起该磁盘版本通知；“重新加载”读取当前文件，有未保存编辑时须确认丢弃，取消保留原文。文件缺失或无法读取不提供无效重载入口，保存仍复核磁盘冲突。开发环境通知回归使用 `scripts/test-disk-change.js`，按既有 Playwright MCP 流程运行；真实 EXE 重载证据见阅读界面验收。

## Markdown 文件打开方式

使用最新版 `artifacts/setup/Marker-Setup-0.1.0.0-x64.exe` 安装或覆盖更新后，Marker 自动注册为当前用户 `.md` 和 `.markdown` 的打开方式。右键 Markdown 文件 → 打开方式 → 选择其他应用 → Marker；选择“始终”即可让后续双击直接使用 Marker。具体按钮文案随 Windows 版本变化。仅直接运行构建目录 EXE 不会执行安装器注册；也可在“选择其他应用”中浏览选取 `Marker.App.exe`。

安装注册不会替换现有默认应用。打开命令对 EXE 与文档路径均加引号，支持中文和空格路径；已有 Marker 窗口时复用单实例文件激活，未保存内容仍沿用原有保护。卸载移除 Marker 候选注册，保留其他程序打开方式及用户文档。

隔离关联验收入口：`./scripts/test-setup-associations.ps1 -SetupPath artifacts/setup/Marker-Setup-0.1.0.0-x64.exe`。脚本需可写当前用户注册表，拒绝已有同 AppId 安装或 Marker 关联，临时安装到工作区 artifacts 内后卸载，检查默认应用与其他程序候选保持不变；不接管已有安装。可选 InstalledCheck 回调在安装期间执行额外原生检查，回调必须关闭自己启动的进程后返回。


## 多文件与悬浮标签

- 用“打开文档”（Ctrl+O）多选文件，或拖入多个 Markdown 文件；左侧圆形按钮显示各文档标题首字，悬停查看完整名称。点击按钮切换文档，悬停或键盘聚焦时显示关闭按钮，也可用 Ctrl+W 关闭当前标签；未保存文档显示小圆点；重复打开相同路径会切回已有标签。
- 切换保留编辑内容与撤销历史，关闭标签或退出窗口时按原有流程选择保存、放弃或取消。另存为的目标如已在其他标签打开，需要先切回该标签处理，避免两个编辑副本覆盖同一路径。
- 标签仅在当前运行内保留；未保存内容仍通过现有恢复草稿处理。后台文件的磁盘变化在切回后检查，保存时仍复核冲突。
- Web 回归入口为 `scripts/test-document-tabs.js`，复用既有 Playwright MCP `browser_run_code_unsafe(filename)` 及本地 Vite 5173。宿主桥接校验随 MSTest 完整测试运行；真实桌面多选、保存确认和退出确认需区分本机验收与 mock 页面结果。
